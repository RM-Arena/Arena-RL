# 边界与扩展点

`bridge.py` 选择一个 Arena 检出目录，并在导入之前设置其资源根目录。`SkillBatch` 共享 Arena 的 `VectorArena`，后者持有相互隔离的常驻 Rust 进程。模拟器仅在初始化期间接受有界的训练初始条件。它不向学习策略暴露任何回合中途的瞬移动作。

`tasks.py` 负责基于种子的场景生成、奖励分量、成功条件与时间限制。所有伤害均来自普通的弹丸/装甲板碰撞。`encoding.py` 是带版本的策略观测/动作契约。它只读取受控队伍的观测。训练宿主可以查看另一队自身的遥测数据来计算奖励，但这些信息被排除在策略特征之外。

`envs.py` 将同一批次适配到 Gymnasium 和 SB3。`SingleRobotEnv` 在终止转移之后需要显式重置。`SkillVecEnv` 在为 SB3 自动重置某个 actor 之前，会保存终止观测和截断标志。actor 子集可以独立重置。

`learning.py` 将 PPO、GAE 与优化过程委托给 Stable-Baselines3。它记录优化前后的校验和、更新次数、源码指纹以及实际样本数。评估使用新的带种子回合和确定性动作。并行 actor 进程运行在 CPU 上；第一版小型 MLP 方案使用 CPU 进行推理/训练。

`hierarchy.py` 冻结相互独立的前哨站/防守技能策略。一个类别型管理器观测合法的局部信息并选择技能。每个选项（option）驱动最多十个真实的底层决策，且不重新初始化模拟器。已完成的 actor 停止推进，等待同伴完成各自当前的选项。场景控制的入侵者无论选择了哪个技能都会继续行动。事件奖励只计一次。终止回放钩子在 actor 重置之前运行。

第一版的局限：W3、红方、单台学习机器人、单一赛季、辅助弹道、平地导航目标、单个坡道、局部突击/拦截课程。初始弹药作为不计入排名的训练初始条件提供。不对全图战略表现、原始图像学习、力矩控制或学习式多机器人协同作任何声明。

扩展方法：定义一个具有明确起点/目标且物理成功条件可测量的任务；必要时在新的模式版本下添加观测字段；训练该技能，并同时与脚本可行性控制器和未训练基线进行对比评估；然后使其可被管理器选择。场地物理和规则的修改应放在 Arena-1 中。

战术执行路径独立于第一个检查点族。`commands.py` 校验带版本的结构化目标。`executor.py` 在底层步之间维护指令身份、目标记忆、进度、取消和终止状态。它显式地按受控槽位自身的相机过滤敌人。`navigation.py` 在不修改模拟器的前提下推导保守的 W3 路线几何。`tactical_encoding.py` 将有界的局部航点以及可见/记忆中的指定目标输入目标条件策略。`tactical_envs.py` 在训练和实时会话中都复用 `VectorArena`。`tactical_runtime.py` 提供与提供商无关的 JSONL 边界，以及一个不等待 LLM 推理的实时控制器。该路径的检查点位于 `checkpoints/tactics` 下；原始的 `checkpoints/w3` 仍作为可复现的基线。

扩展部分新增了 `extended_skills.py`（用于有状态的补给/护送/巡逻/飞行目标）和 `extended_encoding.py`（用于独立的 74 维特征保障/飞行策略），旧的 52 维特征战术模型保持不变。`extended_curricula.py` 通过普通动作制造受伤状态并获取反向飞行许可；它不添加任何修改模拟器状态的钩子。专用飞行是 2026 地图上的任务，而地面战术/保障课程使用 2027。`demonstrations.py` 可选地在 PPO 之前用成功的脚本轨迹初始化新策略；推理过程从不调用它。实际生效的在线能力按赛季和已加载的检查点过滤。场景中包含己方资源计数器，以便外部规划器为补给编制预算。
