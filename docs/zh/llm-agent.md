# DeepSeek 战术规划器与全场对局运行器

Arena-RL 现在拥有一个真实的、基于 API 的战术规划器。DeepSeek 选择一个参数化技能；现有的冻结 PPO 策略只执行**红方 3 号槽位**（当前策略库：串联腿型号 305；旧版 W3 策略库：型号 3）。推理在工作线程上运行，同时模拟器和低层控制器持续运行。API 失败时不会用任何脚本战术策略来替代。

本次集成要求使用的提供方是 DeepSeek V4.1 Flash。其文档中的 API 模型 ID 为 [`deepseek-flash`](https://api-docs.deepseek.com/quick_start/agent_integrations/)。客户端使用 `https://api.deepseek.com/beta/chat/completions`、函数调用以及 `thinking: {"type":"disabled"}`，以实现低延迟决策。它会同时记录请求的模型 ID 和返回的模型 ID。它不使用已被拒绝的 OpenAI 凭据，也不会悄悄替换为其他模型。

## 运行

使用 shell 中已有的凭据。优先使用 `DEEPSEEK_API_KEY`；也支持已有的 `DeepSeek_API_Key` 变量。如需使用其他变量名，请传入 `--api-key-env NAME`。程序从不读取 shell 启动脚本、不存储凭据、不打印授权请求头，也不会把凭据交给模型。

```bash
uv run arena-rl llm-matches \
  --policies checkpoints/serial305 \
  --matches 3 --seed 9000000 --max-calls 150 \
  --output runs/deepseek-full
```

每个 actor 都是一场常规的 **420 秒** 2027 裁判系统对局，只有在游戏规则结束对局时才会提前结束。学习者从常规出生点出发，HP 正常、初始弹量为零、队伍收入正常。补给、伤害、死亡、复活、占领和购买都使用现有模拟器。新技能无法重置其中任何一项。目标完成/失败不会结束比赛；LLM 可以在同一进程中下达另一个目标。

默认运行包含一台红方型号 305 步兵，对阵两台**已声明为脚本控制**的蓝方对手（1 号槽位的型号 2711 重型和 3 号槽位的 W3）。这是一个非对称的单机器人评估，而不是标准的全阵容锦标赛。三种对手配置为 `siege`、`raid` 和 `hunt`；它们分别优先攻击建筑、伺机作战和追击可见机器人。每个控制器只使用本队的合法观测、常规弹药获取方式以及 SDK 路由/瞄准。它们是独立的评估对手，不属于学习得到的红方智能体。不存在被呈现为 LLM 控制机器人的闲置红方队友。

`--matches 1..8` 会并发运行相互独立的 actor。每个 actor 最多只有一个待处理的推理请求；不同对局之间的指令响应不会混淆。`--plan-interval` 是模拟时间间隔（默认 5 秒），在目标完成/失败/复活时会提前发起请求。`--timeout` 限制 API I/O 时长，`--max-age` 拒绝过时的结果，`--max-calls` 限制每场对局的请求数，`--speed` 改变墙钟/模拟时钟的比率。默认速度 1 以实时运行为目标。加速运行必须单独标注，因为此时推理延迟会跨越更多的模拟时间。`--no-verify` 跳过的是确定性回放验证，而不是游戏规则或指令校验。

## 模型接口

API 只接收合法的红方场景：自身机器人/资源、存在时的友方遥测、自身 FPV 视野中的敌人、标注了时效的最近目击记录、公开的基地/前哨站/控制状态，以及公开的地形/阵容上下文。它不会接收蓝方自身的机器人状态、对手资源、脚本配置、回放状态或训练奖励。历史输入限制为最近八次决策及其执行反馈；不请求也不保存模型的内部推理记录。

函数工具暴露的是技能参数，而不是原始运动/开火指令或模拟器操作。宿主代码负责分配指令 ID 和基准 tick。工具集合包括可用技能以及 `continue_current` 和 `cancel_current`；阵容/地图过滤会在没有已部署友方时移除护送，并在 2027 上移除专用飞坡工具。在当前单台红方 305 的 2027 对局中，共有九个技能可用，包括撤退和恢复。同一个规划器客户端也可以由其他宿主提供 2026 `TacticalSession` 及其支持飞行的工具；本对局运行器并不声称提供 2026 飞行基准。

`continue_current` 会保留进度/计时器。语义相同的运行中目标也会被保留，而不是重新开始。新的有效指令会原子性地取消上一个目标。数值范围、目标身份、敌我、公开阵容、受保护建筑以及观测时效由现有的指令/执行器层检查。无效结果会被记录并拒绝；API 超时会让当前 RL 技能继续运行。如果没有有效技能处于激活状态，机器人会等待下一个有效决策。认证错误/提供方永久性错误会终止评估，并保留部分报告/回放；它们不能被报告为完整对局。

现有的 10 Hz 动作编解码器仍使用公开路线提示和弹道辅助。API 集成在对局期间保持所选的 305 运动策略冻结；其再训练另有文档说明。局部作战课程并不能证明全场对局实力。LLM 可以请求导航、补给、攻击、追击、防守和巡逻，但这些请求在物理上可能失败；反馈和原生事件才是证据。

## 产物与解读

每个输出目录包含：

- `decisions.jsonl`：合法请求快照、返回的函数调用、响应 ID、用量、延迟、指令接受/拒绝以及执行状态转换。`advanced_ticks_while_inference` 证明请求期间模拟器时间仍在推进。
- `telemetry.jsonl`：紧凑的逐秒合法红方场景。
- `match-SEED.json` 和 `.commands.json`：带策略摘要的完整原生 v4 回放和指令时间线。
- `report.json`：裁判系统结果、已进行的对局时间、连续性检查、计数/延迟/错误、终局队伍结果、事件、回放验证以及源码/检查点来源指纹。

用量计数器只统计成功解析的响应；对于失败/被丢弃的请求，它们不能当作计费账本。完整对局的回放文件可能很大，保存在被 Git 忽略的 `runs/` 下；选定的摘要/轨迹可以保存在 `evaluations/` 下。将原生 JSON 导入 Arena 的回放页面即可查看。回放会复现记录的物理动作，无需联系 LLM API。

运行器成功退出意味着裁判系统完整结束、有真实被接受的 LLM 指令且连续性成立，而不是承诺获胜。请分别查看记录的结果、无效动作事件、失败技能、死亡和闲置时段。确定性的脚本/mock 测试只验证管线连通性，并被标注为测试替身，而非模型评估。

Arena-RL 在记录本文时为私有仓库；自 2026-10-19 起已公开。Arena-1 中的模拟器前置依赖仍仅在本地，本工作未推送或发布它。


当运行器提供路点目录时，当前规划器只能选择预先验证过的公开路点 ID。宿主将 ID 解析为坐标；手动编写的战术 JSON 仍兼容二元数组。没有目录的自定义宿主使用有界的标量 x/y 对象。参见[串联腿 305 迁移、课程与机械辅助](serial305.md)。早期报告中的历史 W3 结果作为单独的模型/智能体版本保留。
