# 保障、飞行与导航回归结果

于 2026-10-18 在本地测得，所用的 Arena-1 检出版本和 Rust 引擎由各检查点的来源指纹锁定。Arena-RL 在记录本文时为私有仓库；自 2026-10-19 起已公开。Arena-1 的并行环境/场景前置依赖仍仅在本地，尚未推送或发布；因此，全新克隆的公开 Arena-1 目前还不足以复现本次运行。GitHub 自动 CI 检查纯契约部分；模拟器集成需要对应的本地前置依赖，或未来显式选定的 Arena ref。

## 独立种子结果

| 课程 / 指令 | 学习策略 | 随机动作（相同种子） |
| --- | --- | --- |
| 就近弹药 + 治疗（`resupply`） | 18 / 18 | 5 / 18 |
| 跟随移动中的友方前往目的地（`escort`） | 8 / 8 | 0 / 8 |
| 带停留的有序路线（`patrol`） | 10 / 10 | 0 / 10 |
| 专用正向/反向间隙飞越（`fly_slope`） | 40 / 40 | 0 / 40 |
| 导航，包括原先失败的路线 | 32 / 32 | 见原始战术基线 |
| 指定目标作战回归 | 32 / 32 | 见原始战术基线 |
| 区域防守回归 | 32 / 32 | 见原始战术基线 |

保障使用种子 5,000,000–5,000,035。飞行使用 6,000,000–6,000,039：红方正向 6 个、红方反向 9 个、蓝方正向 14 个、蓝方反向 11 个。原始战术回归使用 3,000,000–3,000,031。机器可读的评估/随机动作报告见 `checkpoints/tactics/{support,flight,navigation,combat,defense}`。这些是有限的本地课程计数，而不是全场对局中经过校准的成功概率。

单独进行的在线 `PolicyBank`/`TacticalSession` 验证完成了 **80 / 80** 个目标：从 5,000,000 开始的 40 个保障种子，以及从 6,000,000 开始的 40 个飞行种子。这实际演练了策略族调度，包括“导航到保障”的组合。每次替换都保留了模拟 tick 和弹量；每条指令执行期间都是同一个模拟器进程持续运行。`checkpoints/tactics/validation/runtime.json` 记录了所有结果和所用的策略族。指令下达方是脚本，没有 LLM 推理。

七个代表性原生 v4 回放覆盖了全部三种保障指令以及全部四种赛道/方向的飞行组合。Arena 对护送、补给和巡逻分别确定性地验证了 88、202 和 102 tick；飞行验证对每条反向赛道覆盖 118 tick，正向赛道为 52/58 tick。这些回放中保留了准备动作。原生文件和指令伴随文件位于每个新策略族的 `replays/` 目录中。

## 训练内容

| 策略族 | 种子 | PPO 样本数 | 初始化 |
| --- | --- | --- | --- |
| `support` | 507 | 32,768 | 随机网络权重；4 个并行 actor |
| `flight` | 809 | 16,384 | 成功的脚本示范，然后 PPO；4 个 actor |

保障是一个同时用于补给、护送和巡逻的目标条件网络。飞行尝试了 64 个示范回合（种子 100,809–100,872），保留了 63 个成功回合 / 2,017 条转移。行为克隆运行了 160 个 epoch；元数据记录了其损失、动作拟合度和数据集 SHA256。随后 PPO 在全新的模拟器回合上更新权重。`flight/demonstrations.npz`、`metadata.json`、`metrics.jsonl` 和 `policy.zip` 保留了这些证据。部署时使用网络预测，没有示范脚本回退。最初 32,768 步从零开始的飞行 PPO 试验没有任何成功；在这样小的训练预算下需要进行初始化。

导航/作战/防守权重保持不变。导航修复位于公开路线/动作适配器中，并使用相同的导航检查点和种子进行评估。原有的 52 维特征 schema 保持不变；保障/飞行使用各自独立的 74 维特征 schema。这些技能没有改动模拟器的物理、碰撞和规则。

## 两项导航修复

种子 **3,000,008** 在一个轮子仍位于凸台上时尝试转向，尽管其中心已离开凸台范围。路线适配器现在会在转向前沿现有车轴朝向移动，使车轮的物理接地范围完全离开凸台。种子 **3,000,027** 在尝试越过凸起时压缩了腿；导航现在至少保持常规的 0.245 m 离地高度。使用原有权重，这两个具体场景分别在 **27.6 s** 和 **27.3 s** 内完成。它们的原生回放分别验证了 **552** 和 **546** tick。`validation/navigation-fixed.json` 包含验证哈希和详细结果。

两个较大的原生文件存储为 `navigation/replays/navigation-3000008.json.gz` 和 `navigation-3000027.json.gz`。解压后即可导入 Arena 回放页面或进行验证，例如：

```bash
gzip -dk checkpoints/tactics/navigation/replays/navigation-3000008.json.gz
cd ../RMUC-Arena
uv run rmuc-arena replay verify ../Arena-RL/checkpoints/tactics/navigation/replays/navigation-3000008.json
```

其余所有新的代表性回放均为普通的未压缩 v4 JSON。`checkpoints/tactics/sha256.json` 覆盖已发布的检查点/报告/回放文件。

## 物理任务边界

补给准备阶段会用普通的敌方弹丸使机器人受伤，然后射手停止射击。治疗、弹药获取、购买限制和资源扣除都是模拟器的真实规则。护送使用一个移动缓慢的脚本友方，巡逻使用三个邻近的路线点。可选的接触射击功能可用，但这些计数并未证明在敌方干扰、快速移动的友方、长距离巡逻以及从任意远处接近补给等情况下的表现。

飞行使用真实的 **2026** 650 mm 间隙、两条镜像赛道以及两个方向。反向回合会先在同一回合内完成一次真实的正向飞越，通过常规规则获得通行权限。成功要求在间隙上方真正腾空至少 0.1 s、着地时保持直立、速度低于 1.2 m/s，并保持稳定着陆。适配器负责对齐赛道朝向并使用公开的间隙几何信息；网络负责选择运动、速度、步态、功率、倾斜和跳跃。正向入口容差为 0.11 m，反向对齐容差为 0.055 m。课程从准备位置附近开始，正向出生点带有小幅扰动；没有敌方火力。2027 地图上没有对应的专用飞坡对象。

## 验证命令

```bash
uv run pytest -q  # 63 passed locally
uv run arena-rl evaluate-tactics --checkpoint checkpoints/tactics/support --episodes 36 --seed 5000000
uv run arena-rl evaluate-tactics --checkpoint checkpoints/tactics/flight --episodes 40 --seed 6000000
uv run python examples/validate_extensions.py --episodes 40 --output runs/extended-runtime
```

完整的本地测试套件检查以下内容：旧检查点兼容性、指令校验与原子性拒绝、所有权、预算/接触处理、有序巡逻停留、实际的正向/反向通行权限、两个原先失败的导航种子、保障服务的地图过滤、实时运行、原生回放验证以及学习更新。当前自动化 CI 的契约子集无需未发布的 Arena-1 前置依赖即可运行。这些检查都不能衡量真实高层 LLM 的战术判断能力。
