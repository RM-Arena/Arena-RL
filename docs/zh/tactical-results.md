# 战术执行验证

参考策略在 Arena 现有的 Rust 模拟器上使用 `w3-tactics-v3` 模式。导航策略先训练 32,768 个初始 PPO 转移，再续训 65,536 个转移（共 98,304 个），作战策略训练 65,536 个，防守策略训练 32,768 个。全部使用四个常驻模拟 actor；权重与优化器更新均记录在元数据中。

在独立种子 3,000,000–3,000,031 上以确定性的学习动作进行评估。随机动作基线使用相同的种子。目标选择、公开地图路线提示和弹道瞄准辅助同时作用于基线和学习策略。

| 策略 / 指令 | 完成 | 随机基线 |
| --- | ---: | ---: |
| 导航（包括道路凸起和全场路线） | 30/32 | 0/32 |
| 攻击指定建筑 | 10/10 | 10/10 |
| 与指定机器人交战 | 12/12 | 11/12 |
| 追击指定机器人 | 10/10 | 10/10 |
| 区域防守 | 32/32 | 31/32 |

作战成功指使指定目标损失 60 HP，而非摧毁目标或赢得完整对局。在弹道辅助下，作战课程仍然较为简单。这些数字验证的是指令覆盖与集成，而非更强的作战能力。种子 3,000,008 和 3,000,027 的导航失败保留在评估报告和本地回放中；两者都在反向全场行进时报告 `blocked`。

## 连续任务

种子 4,000,000、4,000,001 和 4,000,002 使用同一个已声明的场景设定（fixture），但模拟器随机性不同。一台 W3 机器人横穿场地，攻击敌方前哨站，返回己方基地入口，以 `blue-1` 为优先目标防守区域，然后追击同一台重型机器人。五个目标在全部三次运行中均完成。指令下发方是确定性测试脚本，而非 LLM。

蓝方重型机器人作为预先潜入者，从己方一侧入口附近出发；它在下达返回基地指令时开始移动，并在追击指令期间远离。场上还有一台距离更近的步兵干扰目标。指令之间没有任何机器人被瞬移或重置。每个阶段都记录前后的 tick 和弹药，并确认使用的是同一模拟器进程。原生回放记录了每一个实际动作。

参考检查点、评估数据行、源码摘要、随机基线、三份任务报告和精选的短原生回放均在 `checkpoints/tactics/` 下进行版本管理。完整的原生任务/评估回放保留在本地 `runs/tactics-v0.2/validation/` 下，以保持 Git 仓库体积较小。可以通过 `examples/validate_tactics.py` 重新生成这些回放。Arena 检出版本必须与记录的引擎/源码指纹一致。

遗留局限：仅支持 W3/红方 3 号位、2027、已记录的敌方型号、辅助瞄准、有限的路线课程以及基于伤害的作战课程。弹药获取、专用的腾空飞坡控制、护送与巡逻仍不受支持。不包含真实的 LLM API、完整对局战略基准或经过校准的技能成功概率。JSONL/运行时集成确实验证了：在规划器延迟期间底层控制会持续进行，且指令可以在不重置回合的情况下切换。

另一项单指令测试仅从 `[4.5, 5.15]` 下达 `attack_structure(blue_outpost)`。它自动同时使用了导航和作战策略，在 22.7 模拟秒后完成，并记录指定前哨站损失 80 HP。对应的完整原生回放保存在本地 `runs/tactics-v0.2/validation/direct-attack.json`。
