# 串联腿 305：撤退、自扶正与安全的 LLM 坐标

当前的单机器人智能体控制**红方 3 号位、型号 305**，这是一款已有的合法串联腿步兵设计。早先的 W3 型号 3 没有完整的自扶正机构。按照用户的选择，当前启用的策略库已针对 305 重新训练；旧的 `checkpoints/tactics` 和 `checkpoints/w3` 策略库仍然保留，作为型号 3 的历史参考。此次迁移没有改动 Arena 的物理、规则和机器人规格。

当前的修正版本为 **0.5.1**；导航/飞坡回归、扩大的独立种子测试以及新的完整对局见[改进结果](serial305-refinement-results.md)。原 0.5.0 的证据仍[单独记录](serial305-results.md)。

## 运行当前智能体

```bash
uv run arena-rl llm-matches --policies checkpoints/serial305 \
  --matches 3 --seed 9000020 --max-calls 150 \
  --output runs/serial305-new
```

使用已有的 `DEEPSEEK_API_KEY` 或 `DeepSeek_API_Key` 环境变量。所选 API 模型仍为 `deepseek-flash`，并关闭思考模式。一台红方机器人由学习策略/LLM 控制；蓝方重型和步兵被声明为独立的脚本控制对手。保留正常的初始弹量、经济收入、伤害、复活以及 420 秒的裁判系统。API 调用是异步的，RL 以 10 Hz 的仿真时间运行。

## 两个新增目标

`retreat` 撤退到可选的安全点 `point`；未指定时则前往己方补给区。它在普通导航/作战的低血量阈值以下仍可执行。到达判定要求低速，超时/失败仍会显式报告。到达补给区并不会凭空产生回血或弹药：后续的 `resupply` 目标使用常规的增益卡、购买和被动回血。

`recover` 让串联腿底盘稳定下来，并等待稳定的直立姿态。恢复也可以作为另一目标的临时子阶段运行，并保留该目标的 ID、仿真 tick、位姿、血量和弹量。继续执行之前，它要求直立度 >0.93、支撑着地、线运动与角运动都较低、没有正在进行的机械扶正，并稳定保持 0.5 秒。有界的超时会报告失败，而不是声称已恢复。恢复失败之后的新命令会开启新的监督区间，但不会改变物理状态。

**机械辅助是显式的。** 305 已有的整周旋转髋关节固件提供物理自扶正力矩。RL 选择局部的稳定/运动/步态动作，并在之后恢复移动；它不学习原始髋关节力矩，也不设置四元数。学习到的停止动作可以保留转向目标，因此底盘可以原地转向。急转弯在平移之前完成，倒退时可以保留更近的轮轴朝向。在公路起伏路段，车身高度和动量保护实现了公开的底盘离地间隙要求。

路径规划使用公开的几何信息：坡道入口/出口作为一次确定的转移整体完成，各通道口按合法路径代价而不是直线距离进行比较。公开的地形/墙体栅格可以连通通用 SDK 保守路点图所遗漏的路线。局部脱困会先沿底盘轮轴方向后退，再尝试下一次转向。这些辅助功能都不会改变碰撞体、禁区或底盘功率限制。所有电机行为仍由原始 Rust 引擎实现。

## 坐标生成

集成规划器现在选择**预先验证的公开路点 ID** 和防守区域 ID。坐标由宿主端解析。目录中的点会依据底盘离地间隙、障碍物和禁区进行过滤。`attack_structure`、`defend_region`、`resupply` 等战略工具已经包含导航；提示词不鼓励不必要的短距离 navigate/cancel 循环。

DeepSeek 使用其位于 `https://api.deepseek.com/beta` 的[严格函数调用端点](https://api-docs.deepseek.com/guides/tool_calls/)。函数参数采用封闭的对象 schema，并经过宿主端校验。没有路点目录的自定义宿主仍可使用严格类型的 `{x, y}` 对象，在提交命令前检查数值是否有限、是否处于当前场地边界内。公开的战术协议继续接受二元坐标数组，以保持对现有客户端的兼容。未知的目录 ID、格式错误的坐标和过期的决策都会保持当前活动目标不变。凭据永远不会进入模型输入或日志。

## 训练

| 策略族 | 受控型号 | 新增 PPO 样本 | 初始化 | 观测约定 |
| --- | --- | --- | --- | --- |
| 作战（combat） | 305 | 32,768 | 成功示范 + PPO | 52 维特征 |
| 保障（support） | 305 | 32,768 | 成功示范 + PPO | 74 维特征 |
| 防守（defense） | 305 | 32,768 | 成功示范 + PPO | 52 维特征 |
| 机动（mobility） | 305 | 初始 32,768 + 组合微调 8,192 | 160 条成功示范、显式父策略初始化 + PPO | `serial305-mobility-v1`，64 维特征 |
| 导航（navigation） | 305 | 原始 16,384 + 局部细化 16,384 | 保留原网络用于 4 m 以外的远距离转移；细化网络用于局部接近 | `serial305-navigation-v1`，64 维特征 |
| 飞坡（flight） | 305 | 新增 8,192 | 183/192 条成功示范，然后以 5e-6 进行 PPO | `serial305-flight-v3`，84 维赛道相对特征，2026 赛季 |

所有策略族都使用四个并行 actor。元数据记录型号/赛季/schema、父策略或示范的来源指纹、PPO 样本数/更新次数以及 PPO 前后的权重哈希。跨策略族初始化要求受控型号和特征/动作约定一致。部署的策略库会拒绝混用的型号 ID，并要求 305 使用训练好的机动策略。显式指定的阵容会被校验，而不会被静默改写。

机动课程包括：

- 通过普通的跳跃/侧倾/腿部命令撞向地图边缘，引发真实的前翻、侧翻和顶部着地翻倒，随后进行稳定。不使用初始四元数，也不在回合中途编辑位姿。
- 在真实弹丸伤害、被击毁并以 **10% 血量**正常自动复活之后撤退，并带有裁判系统真实的虚弱/保护状态。
- 记录到的中央路沿接触（约 `(14.52, 2.23)`）和高地位置（约 `(11.1, 6.51)`），包含合法的坡道出口和脱困动作。
- 补给区墙体接触（约 `(3.89, 13.43)`），既有短距离前进目标，也有撤退到补给区的目标。
- 物理摔倒后在同一命令 ID 下继续撤退，而不是停在恢复目标上。

共有八种带有界扰动的模板变体，而不是 64 种互不相关的地图几何。组合微调集包含 160 个成功回合（20,317 条转移）；示范之后实际发生的 PPO 权重更新单独检查。在恢复过程中，无论恢复是显式命令还是临时中断另一目标，意图特征都完全相同。局部卡滞检测器使用命令实际的到达半径，因此也能捕捉学习策略在目标区域外不远处停下的情况。

这些是物理准备序列，并保留在原生回放中。受伤课程中的射手在准备好状态后就停止射击；这并不能证明策略学会了在任意持续火力下躲避子弹。完整对局另行检验持续的对抗。

```bash
uv run arena-rl train-tactics --family mobility --model-id 305 --steps 32768 --envs 4 --seed 1801 --output runs/mobility-new
uv run arena-rl train-tactics --family navigation --model-id 305 --initialize-from checkpoints/serial305/mobility \
  --steps 16384 --envs 4 --seed 1711 --output runs/navigation-new
uv run arena-rl evaluate-tactics --checkpoint checkpoints/serial305/mobility --episodes 64 --seed 7000200
uv run python examples/evaluate_composed_navigation.py --output runs/composed-navigation.json
uv run python examples/validate_recovery.py --output runs/physical-regressions
```

训练使用了已记录的源码快照/哈希以及保存下来的示范数据集。路径/安全集成随后得到修复并经过独立评估；使用当前辅助功能重新训练，不保证能复现字节完全相同的权重。原生动作回放无需推理即可确定性地验证。

## 证据与局限

见 `checkpoints/serial305` 下的评估报告以及[完整对局证据](serial305-results.md)。最终的独立种子机动测试使用种子 7,000,200–7,000,263：27 个显式恢复目标和 37 个撤退目标。撤退包括先恢复再撤退的组合。物理回归测试还保存并确定性地验证了具有代表性的原生回放。在相同种子上与空闲/随机策略的对比，区分了已有固件的贡献与真正有用的学习运动。一个完成的 `recover` 命令可能一开始就处于直立状态；`recoveries_completed` 是执行计数器，而不是真实翻倒的次数。原生的 `self_righting`/`self_righted` 事件和位姿采样单独报告物理事件。

原有的 32 例导航回归和 32 例飞坡回归现已全部通过。更大范围的扰动赛道仍存在失败；[改进报告](serial305-refinement-results.md)将其确切数量与这些回归集分开给出。串联底盘仍可能被机械卡死或耗尽功率预算。仅凭少数几场对局，不能得出全局胜率或普适恢复保证。飞坡迁移使用其自身的 2026 课程，在 2027 对局中不能作为专用地图技能使用。

## 改进的飞坡控制器

305 飞坡策略现在有 84 个输入：带版本的物理路线特征，加上显式的接近/对准/助跑/腾空/着陆/恢复阶段、起跳状态、间隙占用、沿赛道速度以及着陆距离误差。它使用赛道相对坐标系，并屏蔽不应影响这一运动技能的云台、弹药和经济字段。W3 以及归档的 305 `w3-flight-v1` 策略保留其 74 输入的评估路径。未发布的中间版纯阶段原型属于开发运行，并非发布的策略。

入口对准在起跳前检查横向误差是否低于 25 mm、朝向以及支撑是否稳定。地面自扶正监督不会打断正常的空中倾斜；恢复激活期间仍会观测物理滞空时间。着陆仍要求真实地腾空跨越间隙、底盘直立着地，并满足原有的低速/保持条件。向前跳跃使用有界的普通行程；当网络在间隙底部请求再次跳跃时，则使用全部可用行程。actor 从不设置车身位姿或血量。成功示范的收集包含物理意义上的间隙边缘重试动作，而不是丢弃所有此类尝试。

细化后的导航网络在距目标 4 m 以内使用。一个显式记录的冻结转移网络保留了之前的长距离行为；恢复和局部脱困保持原有监督。两个网络共享型号 305 的 64 输入约定，完整对局报告会记录两个策略的摘要。
